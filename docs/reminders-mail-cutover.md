# 提醒事项邮件来源切换（2026-10-12）

## 本次范围

- Meet summary API 和 summarize worker 必须使用同一版代码。
- 提醒事项只展示 2026-10-12（含，当地会议日期）起邮件纪要中的个人待办；按参会姓名精确归属，通过参会邮箱查询。
- 任务及持续职责全部保留。仅同人、同类型、同文字、同期限完全相同的记录合并；原始来源保存在追加事件中。
- 已处理过的原转录不阻挡邮件导入。已导入邮件重复执行幂等；邮件内容变更、姓名归属不明确需人工核对，不能算成功。
- 旧个人记忆不删除。新查询规则不展示未从邮件导入的旧记录。

## 部署前必须完成

1. 备份持久化的 state.sqlite3（包含 WAL 的一致性备份）。
2. 导出 2026-10-12 起实际存储的已发邮件纪要、对应原始转录、recording source ID 和完整参会人姓名/账号/邮箱。不能重新调用模型生成替代原邮件。
3. 导出 JSON 数组，各项包含 source、summary、transcript、participants。
4. 在独立副本预检：`python -m summary.core.preview_mail_reminders --database state.sqlite3 --tenant meet --bundle delivered-mail.json`。工具只读取原库，在临时副本中导入，输出逐会议结果及各邮箱清单，不改线上数据。
5. 逐人对照原邮件核对数量及内容。任何 needs_review 都须处理后重检；不得忽略。北北目前已核对两场邮件应有 7 条，而不是旧数据库的 7 条。

## 发布顺序与验收

预检通过后，在受控发布窗口备份并执行同一 ingest_summary 导入逻辑，再切换 summary API 和 summarize worker。不要先切换查询再等待补数据，否则可能暂时显示空列表。预检工具不提供线上写入开关；线上导入是单独的运维步骤。

AfB 同步部署 codex/profile-email 分支中的 afb-user 类型透传改动；Meet 地址及密钥沿用当前配置，不需新的 AfB SQL。

验证各邮箱仅见本人任务、日期降序、持续职责保留、重复导入不增项、完成及撤销状态保存。旧队列任务没有邮件正文时返回 needs_review，不能重新提取原转录。不要重发会议邮件。

本提交只包含代码、隔离测试和预检工具；真实邮件全员预检、线上导入及部署尚未执行。
