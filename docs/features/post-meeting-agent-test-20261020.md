## 测试发现与修复

1. 原邮件阶段与任务出箱之间交接中断：增加持久化预留及仅对尚未执行交接的恢复；不盲目重发状态不明的邮件。
2. SDK 原生绑定需要临时目录可执行：修正任务容器 /tmp 挂载，保留只读根目录及其他隔离限制。
3. 初始 API 模板地址不适用于 SDK Messages 接口：改为 `https://api.deepseek.com/anthropic`，密钥不变。
4. 模型可能执行参考纪要中的其他任务：执行提示限定当前 task，控制器核对附件类型与该任务一致。
5. 正常 PPT 的打印机设置二进制曾被误拒绝：仅允许精确路径、官方内容类型且有大小上限的打印设置；仍拒绝宏、OLE 及其他未允许的嵌入二进制。
6. 收紧最终 JSON 输出，记录有界错误类别，避免把原始 SDK stderr 或密钥写入日志。
7. 独立检查器曾把说明文字误判为销售任务，已修正任务匹配。一次使用旧镜像的测试已作废，增加源码与镜像哈希保护。

最终 PPT 首次生成仍发生 RuntimeError；一次诊断及明确控制的补跑后成功，其他成功阶段复用检查点。不能据此次验收宣称所有任务首次自动成功，也不能声称已证明生产可靠性或科研收益。失败记录保留，不清空账本重跑。
